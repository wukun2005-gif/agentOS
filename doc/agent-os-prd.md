# 一、背景与目标

## 1.2 目标用户画像

### 用户类型优先级

| 优先级 | 用户类型 | 核心需求 | 典型场景 |
|--------|----------|----------|----------|
| **P0** | **打工人（核心）** | 生产力工具、效率提升 | 邮件、会议、文档、沟通 |
| P0 | 程序员 | 代码、文档、Git、Debug | 代码搜索、Code Review、调试 |
| P0 | 产品经理 | 需求、文档、会议、协调 | PRD撰写、项目跟进、跨团队协作 |
| P1 | 设计师 | 设计稿、素材、协作 | 设计评审、规范维护、素材管理 |
| P1 | 管理者 | 决策、汇报、团队管理 | 会议、决策、绩效分析 |
| P2 | 家庭用户 | 娱乐、生活便利 | 天气、音乐、提醒 |

### 为什么打工人是核心用户？

| 维度 | 数据 |
|------|------|
| 市场规模 | 全球知识工作者超10亿人 |
| 痛点强度 | 45%员工认为工具让他们更不productivity |
| 付费意愿 | 企业AI工具市场预计2026年达$500亿+ |
| AI价值 | 68%企业报告AI减少了30%以上的手动工作 |

## 1.3 Agent OS价值主张

### 核心洞察

> **用户有明确意图，但OS要求手动翻译为GUI操作。**

传统OS的工作方式：
```
用户意图 → 打开App → 导航菜单 → 找到功能 → 执行操作 → 获取结果
```

Agent OS的工作方式：
```
用户意图 → AI理解 → 自动执行 → 结果涌现
```

### 解决方案

**消除"意图→操作"的翻译成本。**

| 传统OS | Agent OS |
|--------|----------|
| 用户需要知道功能在哪里 | 用户只需要说出意图 |
| 用户需要在多个App间切换 | AI自动跨App协作 |
| 用户需要手动整理信息 | AI自动聚合和摘要 |
| 用户需要记住操作步骤 | AI学习用户习惯并自动化 |

### 差异化定位

> **克制的、环境式的AI存在，不是又一个聊天框。**

| 竞品 | 形态 | 问题 |
|------|------|------|
| ChatGPT/Claude | 聊天框 | 需要用户主动发起，无法自动执行 |
| Siri/Alexa | 语音助手 | 功能有限，无法处理复杂工作流 |
| Rabbit R1 | 硬件设备 | 硬件先行失败，弃用率95% |
| **Agent OS** | **双层光+星座产物** | **环境式存在，意图驱动，自动执行** |

## 1.4 Demo目标

### 可测目标

| 目标 | 验收标准 |
|------|----------|
| 5秒在场感 | 打开即感知"有个活着的系统待命" |
| 3分钟价值传递 | 用户在3分钟内理解核心价值 |
| 高频场景覆盖 | 覆盖邮件、会议、沟通3个最高频场景 |
| 效率提升可视化 | 量化展示时间节省（如"每天节省2小时"） |

### Non-Goals（P0不做）

| 不做 | 原因 |
|------|------|
| 真实LLM API调用 | 验证的是范式，不是模型准确率 |
| 真实系统权限 | 只模拟，不真正发邮件、改日历 |
| 多用户/持久化 | Demo阶段不需要 |
| 完整无障碍审计 | 但必须支持键盘+reduced-motion |

# 二、调研发现：打工人高频高摩擦高价值操作

## 2.1 按职业角色分析

### 2.1.1 程序员/开发者

**每天工作流程：**
- **8:00-9:00** 晨间启动：查看Git变更、代码审查请求、Jira任务
- **9:00-12:00** 深度编码时段：编写代码、调试、单元测试
- **12:00-13:00** 午间：快速处理紧急邮件和消息
- **13:00-17:00** 协作与维护：Code Review、会议、文档编写、部署
- **17:00-18:00** 收尾：提交代码、更新任务状态、规划明日工作

**高频操作：**

| 操作 | 频率 | 时间成本 | AI提效潜力 |
|------|------|----------|------------|
| 代码搜索 | 每天15-20次 | 每次2-5分钟 | 高（语义搜索） |
| 文档查阅 | 每天10-15次 | 每次3-8分钟 | 中（智能摘要） |
| Git操作 | 每天20-30次 | 每次1-3分钟 | 中（自动化） |
| Code Review | 每天2-5次 | 每次15-30分钟 | 高（AI审查） |
| Debug | 每天3-5次 | 每次15-60分钟 | 高（智能诊断） |

**TOP 3痛点：**

1. **上下文切换成本高**：开发者需要10-15分钟才能恢复到代码编辑状态，完全重建上下文需要30-45分钟
2. **信息分散**：代码、文档、问题跟踪分布在多个工具中
3. **重复性工作**：样板代码、测试编写、文档生成

**AI替代机会：**
- 代码补全和生成（GitHub Copilot、Cursor）
- 智能Code Review（CodeRabbit、PR-Agent）
- 自动化测试生成（Codium AI）
- 语义代码搜索（Sourcegraph Cody）
- 自动化文档生成（Mintlify）

## 2.2 按工作场景分析

### 2.2.1 晨间启动（9:00-10:00）

**典型场景：**
- 打开邮箱：平均117封邮件/天
- 查看IM：平均153条Teams消息/天
- 检查日历：当天会议安排
- 处理紧急消息

**痛点：**
- 信息量过大，难以判断优先级
- 从被动响应开始一天，而非主动规划
- 认知资源在上午最充沛时被消耗

**AI价值：**
- 智能摘要：自动生成"今日简报"
- 优先级排序：AI判断哪些需要立即处理
- 草稿回复：预生成邮件/消息回复
- 日程建议：基于优先级推荐时间安排

---

### 2.2.2 深度工作时段（10:00-12:00）

**典型场景：**
- 编码、写作、设计、分析等高认知任务
- 平均专注时间仅13分钟7秒
- 每2分钟被会议、邮件、聊天打断

**痛点：**
- 注意力难以维持
- 上下文切换成本高（每次切换需9.5分钟恢复）
- 深度工作时间占比不足25%

**AI价值：**
- 通知过滤：智能判断哪些可以延迟
- 上下文保存：中断后快速恢复
- 任务自动化：处理低认知任务
- 进度追踪：自动记录工作进展

---

### 2.2.3 午间碎片（12:00-14:00）

**典型场景：**
- 午餐时间处理非紧急事务
- 回复上午积压的消息
- 处理行政性工作

**痛点：**
- 午休时间被侵占
- 无法真正休息
- 下午精力不足

**AI价值：**
- 批量处理：自动回复常见消息
- 行政自动化：报销、审批等
- 智能提醒：标记需要下午处理的事项

---

### 2.2.4 下午协作（14:00-17:00）

**典型场景：**
- 会议密集时段

- 实时会议转录和摘要
- 自动提取行动项并分配
- 会议效果评估
- 替代性沟通建议（邮件/异步视频）

### 2.2.5 收尾复盘（17:00-18:00）

- 当日工作总结

## 3.10 市场空白点分析

### 3.10.1 AI存在形态的两极分化

**现状**：
- **太重**：ChatGPT/Claude等聊天框，需要用户主动发起
- **太轻**：Siri/Alexa等语音助手，功能有限
- **硬件失败**：Rabbit R1、Humane AI Pin证明硬件先行成本高

**空白**：缺少克制的、环境式的AI存在形态

**机会**：Aura OS的"双层光+星座产物"形态

---

### 3.10.2 从"被动响应"到"主动执行"

**现状**：
- 大多数AI仍需用户主动发起对话
- AI提供建议，但不自动执行
- 用户仍需手动确认和操作

**空白**：缺少能主动理解意图并自动执行的AI

**机会**：Agent OS的意图驱动+自动执行

---

### 3.10.3 从"App切换"到"意图直达"

**现状**：
- 用户需要在多个App间切换完成任务
- 每个App有自己的AI（如果有的话）
- 跨App协作需要用户手动协调

**空白**：缺少跨App的统一AI入口

**机会**：Agent OS作为统一入口，协调多App协作

---

### 3.10.4 从"信息展示"到"结果生成"

**现状**：
- AI以展示信息为主（搜索结果、聊天回复）
- 用户仍需手动处理信息
- 缺少自动化执行能力

**空白**：缺少能直接生成结果并执行的AI

**机会**：Agent OS的"星座产物"直接呈现可执行结果

---

### 3.10.5 缺少克制的、环境式的AI存在形态

**现状**：
- AI要么太重（聊天框），要么太轻（语音助手）
- 要么打断工作流，要么功能不足
- 缺少"在场但不打扰"的AI形态

**空白**：缺少克制的、环境式的AI存在

**机会**：Aura OS的"双层光"形态——边缘弱感知+中心强交互

---

# 四、设计方案：AI Agent如何解决打工人痛点

## 4.1 系统架构

```
用户意图 → 光球状态流转 → 意图路由 → Agent执行 → 结果涌现
    ↓           ↓            ↓          ↓           ↓
 文字/语音   8态状态机    关键词/LLM  多Agent协作  星座产物
```

### 架构分层

```
表现层（Presentation）
  └── React组件树: Orb / Dock / SystemTray / Window / CardLayer

状态层（State）
  └── Zustand store: orbState + windows + notifications + tasks

逻辑层（Logic）
  └── IntentRouter / AgentOrchestrator / ArtifactFactory

输入层（Input）
  └── TextInput（P0）→ SpeechRecognition（P1）

执行层（Execution）
  └── EmailAgent / MeetingAgent / DocumentAgent / TaskAgent
```

---

## 4.2 核心功能模块

### 4.2.1 智能晨间简报

**触发方式**：
- 用户打开OS自动显示
- 用户说"今天有什么重要的？"
- 用户说"早上好"

**执行流程**：
1. 聚合多源数据：邮件、IM、日历、任务
2. AI分析优先级：基于发件人、内容、紧急程度
3. 生成结构化简报：关键事项、待办、会议
4. 展示在光球周围

**展示形式**：
- 光球周围涌现3-5个关键信息卡片
- 每个卡片包含：类型图标、标题、摘要、操作按钮
- 用户可点击卡片展开详情

**价值量化**：
- 原来：60分钟处理晨间信息
- 现在：5分钟掌握全天要点
- **节省：55分钟/天**

---

### 4.2.2 邮件AI助手

**触发方式**：
- 用户说"看看邮件"
- 用户说"有什么重要邮件"
- 用户说"帮我回复邮件"

**执行流程**：
1. **智能分类**：
   - VIP邮件（老板、客户、合作伙伴）
   - 需要回复（有明确行动项）
   - 可稍后处理（信息性邮件）
   - 可自动回复（常规通知）

2. **优先级排序**：
   - 基于发件人关系
   - 基于邮件内容紧急程度
   - 基于用户历史行为

3. **一键回复**：
   - 基于邮件上下文生成回复建议
   - 用户确认后自动发送
   - 支持多版本选择

4. **跨应用联动**：
   - 邮件中的会议邀请 → 自动添加到日历
   - 邮件中的任务 → 自动创建待办
   - 邮件中的文档 → 自动归档

**展示形式**：
- 邮件卡片从光球涌现
- 每个卡片包含：发件人、主题、摘要、优先级标签
- 可展开查看详情和回复建议

**价值量化**：
- 原来：11.7小时/周处理邮件
- 现在：5小时/周（AI处理60%常规邮件）
- **节省：6.7小时/周**

4. 生成会前准备材料

**展示形式**：

**执行流程**：
1. 实时语音转写

4. 实时显示关键信息

**触发方式**：
- 用户说"会议结束了，帮我整理纪要"

3. 自动生成邮件发送给参会人
4. 自动更新项目文档

**展示形式**：
- 会议纪要卡片：决策、待办、文档
- 操作按钮：同步到Jira、发送邮件、更新文档

**价值量化**：
- 原来：1.5-2小时整理会议纪要
- 现在：0（自动生成）
- **节省：1.5-2小时/次会议**
