Aura OS：无 App 时代的 AI 存在机制

把三份 PRD 的真正优点合成一个可 vibe coding 的 MVP——不是拼文档，而是重定设计方案。

2026-08-14 · 独立调研 + 三份评估共识 · 文件：doc/prd-aura-merged.html

一句话方案：AI 以「双层光」存在——边缘浸润 + 中心聚焦；用「空间收拢 + 意图复述」表达听懂；任务结果以「星座产物」从光核涌现，近场活跃、远场沉静，禁止列表堆叠。

01本题要什么（评测锚点）

原题要求：用克制视觉/动效设计「无 App」AI 存在机制，并回答：

Q1 形态

AI 以什么形态存在于系统中？

Q2 反馈

如何表达「我在听，并且我懂了」？

Q3 涌现

任务/信息如何以非 App、非列表形态自然出现？

交付约束：vibe coding 可运行 Demo；面试约 5 分钟能讲清并演示。

三份评估的硬约束（必须满足）

  • Q3 若做成底部卡片堆叠 = 列表变体 = 直接扣分（Intent OS 主失分点）。
  • Q2 若只有光效、没有意图复述 = 信任断裂（Aura OS 主失分点）。
  • Q1 若只有边缘光或只有居中大球，都偏科；混合形态得分最高（Energy Orb 方向正确）。
  • PRD 必须有 Non-Goals、可测成功标准、错误态、文字降级——否则 vibe coding 会乱加功能。

明确摒弃（写进 Non-Goals 的产品理由）

底部/通知式卡片流

垂直堆叠+左右滑 = 通知中心变体。直接违反「非列表」。Intent OS 的 Q3 整段丢弃。

纯光效「我懂了」

用户无法校验 AI 是否理解对。Aura 的致命洞。无文字复述不进 MVP。

拟人角色/兔子头像

恐怖谷 + 变成「又一个助手 App」。抽象光，不去拟人。

P0 接真 LLM / 真 OS 集成

面试验证的是范式，不是模型准确率。预设意图路由即可。

对外暴露 8 态按钮

工程可有子阶段；演示只保留 5 主态 + Error。过细状态机伤害可讲性。

把星轨留到 P2

那是 Q3 的差异化答案。Energy Orb 原优先级错误——本 PRD 纠偏为 P0。

03产品目标与 Non-Goals

目标（可测）

  1. 5 秒在场感：打开即感知「有个活着的系统待命」，不是空白页或聊天框。
  2. 800ms 内懂的反馈：提交意图后，先出现复述，再出产物。
  3. 非列表可读：≥2 个产物时仍是环绕布局；≥4 个时出现远场沉静，而非无限列表。
  4. 无麦可演：纯文字路径跑通全流程。
  5. 克制：Idle 时屏幕 ≥85% 留白；动效可被 prefers-reduced-motion 关掉。

Non-Goals（P0 不做）

  • 真实系统级权限（发短信、支付、改日历）——只模拟。
  • 真实 LLM API、持久化账号、多用户。
  • 3D/WebXR/Three.js。
  • 唤醒词、本地大模型、插件商店。
  • 完整无障碍审计（但必须支持键盘取消 + reduced-motion + 状态文本）。

04设计答案：三个问题怎么答

Q1 · 双层光（Dual Aura）

边缘 Flare：始终极弱存在，用余光告知「系统在」——学 Siri 边缘光与 Calm Technology「利用边缘感知」。

中心 Core：交互时聚焦，承载状态语义——学 Aura「光即 AI」，但 Idle 时弱化，避免 ChatGPT Orb 式打断。

Idle：Flare 可见、Core 低对比。Active：Core 主导、Flare 跟色。

Q2 · 听 + 懂协议

听：Listening 外缘脉动 +（可选）声波；转写 interim/final。

懂：Understanding 光核向内收拢（空间隐喻）+ 一句意图复述。

低风险（查天气）隐式确认后继续；高风险（提醒/外部动作）显式确认按钮。对齐 Google Conversation Design。

Q3 · 星座产物（Constellation）

结果从 Core「生长」到近场扇区；相关操作为卫星微泡。

新产物找空槽，不重排旧产物（NN/g：乱变 UI 伤可用性）。

完成且未固定 → 退远场降饱和；禁止底部堆叠列表。

状态机（对外仅此）

状态光用户所见退出
idle5s 呼吸；Flare 低亮极简待命点击/空格/输入
listening快速脉动；Flare 提亮转写停顿 1.5s / 提交 / Esc / 8s 静音
understanding向内收拢 + 紫复述气泡解析完成 / 需澄清
thinking慢旋短状态文案完成 / 超时 / 取消
responding暖色绽放星座产物出现追问→listening；空闲→idle
error红短脉冲后静止原因 + 重试/改文字恢复动作

07用户与场景（面试官也是用户）

面试官

5–10 分钟判断你有没有跳出「又一个聊天框」。痛点：看过太多 Siri 克隆。

Vibe Coder

需要触发→行为→所见→验收四件套，而不是「做个有感觉的 AI UI」。

终端体验者

习惯找图标。需要引导式空状态，而不是说明书。

主路径（编号，可直接编码）

  1. 打开 Demo → Idle：边缘光弱呼吸，中心核低对比。
  2. 点击 Core / 按空格 → Listening；输入「明天北京天气」。
  3. 提交 → Understanding：核收拢；出现「明白，你想查明天北京的天气」。
  4. → Thinking（约 800–1200ms）→ Responding：天气产物从核生长到右侧近场。
  5. 再发「放首歌」→ 音乐产物出现在左侧空槽；旧天气产物位置不变。
  6. 再发第三条 → 最旧产物降为远场（低饱和）；近场保持可读。
  7. Esc / 错误路径：无权限或空输入 → Error，提供「改用文字」。

P1 — 增强但不阻塞演示

  • Web Speech + 能力检测降级；Analyser 波形。
  • 风险分级显式确认（提醒类）。
  • 产物展开/固定/关闭；追问续接上下文。
  • Canvas 粒子/涟漪增强（可关）。

P2 — 以后

  • 真 LLM Function Calling；TTS；唤醒词；多设备；记忆。

09技术与 vibe coding 约束

  • 栈：Vite + React + TypeScript；CSS 动画为主；Zustand/useReducer 管状态。
  • P0 禁止：CDN 字体/图表库作为演示依赖；页面离线也应能演主路径。
  • 模块边界：OrbView / StateMachine / IntentRouter / ArtifactFactory / SpatialLayout / A11yStatus。Router 不得直接改动画时长或权限。
  • 语音：SpeechRecognition 不可用时静默降级文字（MDN 兼容性现实）。
  • 动效：呼吸 5s；切换 150–400ms；尊重 reduced-motion。

给编码 Agent 的写法

每个任务必须写成：触发 → 系统行为 → 用户所见 → 验收。例如：

当用户在 Listening 提交「明天北京天气」→ 进入 Understanding，Core 400ms 收至 0.9 并变紫，底部复述「明白，你想查明天北京的天气」→ 1s 内进入 Thinking → Responding 时在右侧近场生成天气产物 → 验收：无复述不得出现产物；Esc 任意时刻回 Idle。

105 分钟演示脚本

  1. 0:00–0:30 命题：找 App → 交 Intent；指出双层光 Idle。
  2. 0:30–2:00 走通天气：听→收拢→复述→产物。强调「懂了」不是闪一下。
  3. 2:00–3:20 连续第二、第三个意图，展示星座近场/远场，对比「这不是通知列表」。
  4. 3:20–4:20 故意 Error（空提交/未知意图），展示可恢复。
  5. 4:20–5:00 收束三原则：双层光、确认协议、星座涌现；邀请面试官输入一句。
